01 // Description

A payment is a state change plus a legal claim. This course follows that claim across rails — cards, ACH, wire, FedNow/RTP, SWIFT, and the ISO 20022 migration — and then across the overlay: wallets, processors, banking-as-a-service, open banking and data rights, and stablecoins used as settlement rather than as a speculative asset. The course is not a cryptocurrency elective and is distinct from FINTECH 520’s product survey.

Advantage in this market does not accrue to the first lightning-fast front end. It accrues to whoever controls identity, the software layer above the rail, and the orchestration that conceals decades of infrastructure behind a single authorization. Students model authorization, clearing, settlement, and failure: returns, chargebacks, correspondent liquidity, ledger behavior under load, and what breaks when an automated agent initiates a real-time payment instead of a person.

Coursework is quantitative and produces both numbers and systems: unit economics of a rail, a settlement-risk ledger, a returns and exceptions engine, and a fraud-score versus false-positive curve. Deliverables live on GitHub Pages so an operator can use the plot. Emphasis is on the seams the incumbent stack does not already own — embedded pay-in and pay-out, commercial and cross-border flows, reconciliation and exceptions, agent-initiated checkout, and settlement that must still land at a bank.

AI is encouraged for code and document extraction; the student remains responsible for interchange math, liquidity, and the failure case.

02 // Optional Textbook

No required textbook. Primary documents: network fee schedules, NACHA operating rules excerpts, FedNow / RTP product sheets, a card-scheme chargeback reason-code table, an ISO 20022 message sample.

Useful desk reading (not cover-to-cover): a current payments-industry primer; BIS / Fed papers on instant payments and wholesale settlement. Scheme PDFs beat a textbook for this course.

03 // AI Policy
AI use is highly encouraged. You may use any model to write orchestration code, parse a scheme PDF, or draft a memo. You remain solely responsible for everything you turn in: the simulator runs, the unit economics are correct, a reader can follow the state machine without asking the tool what you meant. If settlement risk is mis-sized or the chargeback tree is wrong, that is your grade.

05 // Learning Objectives
01 Draw the state machine of a payment on any major rail: who is principal at authorization, clearing, and settlement; when the legal claim moves; what a return or chargeback undoes.
02 Compute unit economics: interchange + scheme + acquirer + processor + fraud + rewards + cost of float + cost of capital on delayed settlement. Show contribution margin at the transaction and at the portfolio.
03 Size settlement and correspondent liquidity: net vs gross, pre-funding, in-flight exposure, what a delayed ACH batch does to cash. Plot exposure through a day.
04 Build failure systems: returns, chargebacks, R-codes, exception queues. Measure false-positive cost of a fraud rule, not only AUC.
05 Place a firm on the stack. Name who already owns identity, the rail, and the orchestration. Specify the adjacent seam (embedded, cross-border, recon, agent-checkout, bank-landing stablecoin settlement) and build a thin version.
06 Publish on GitHub Pages. Defend the ledger and the P&L without a teammate as proxy.
06 // Tentative Course Schedule
Block 1 — State change + legal claim
  • Authorization, clearing, settlement as three clocks
  • Who is principal: issuer, acquirer, network, correspondent, TCH, the Fed
  • ISO 20022 as a message, not a religion
  • Lab: draw one card payment and one ACH credit as state machines; list every ledger that moves
Project 1 — Unit economics of a rail
  • Interchange + scheme + acquirer + processor + fraud + rewards + float
  • Same $100 sale on card vs ACH vs FedNow; contribution at txn and at 10k txn/day
  • Sensitivity: mix shift, interchange regulation, a 40 bp fraud spike
  • Deliverable: workbook + Pages waterfall plot an operator would recognize
Block 2 — Rails
  • Cards: dual-message vs single-message, chargeback windows
  • ACH: batch, returns (R01–R29 that actually matter), same-day ACH
  • Wire / SWIFT / correspondent: nostro, cover payments, liquidity at the correspondent
  • FedNow / RTP: instant, irrevocable-ish, what “request for payment” changes
  • Lab: latency and finality table; plot in-flight exposure by rail through a business day
Project 2 — Settlement-risk ledger
  • Simulate a processor’s day: captures, batch ACH, instant payouts, incoming returns
  • Cash, payables to merchants, receivables from networks, pre-funded RTP balance
  • Break the day: a delayed ACH window, a scheme outage, a 2% return spike
  • Deliverable: time-series ledger + max intra-day hole you would have to fund
Midterm quiz — closed book. State machines, fee stack, a liquidity number. Study guide one week prior.
Spring Break
Block 3 — Failure, fraud, identity
  • Chargebacks and R-codes as a P&L, not a support ticket
  • ATO and APP fraud vs AML clocks (milliseconds vs SARs) — do not mix them
  • Identity: who owns KYC when the front end is a BaaS partner
  • Lab: score a txn stream; plot precision-recall and $ cost of false positives
Project 3 — Exceptions engine
  • Queue: returns, chargebacks, mismatches, agent-initiated payments that bounce
  • SLA vs capital: how long can an exception sit before it is a hole
  • Deliverable: Pages ops console + the expected-loss number of leaving the queue unworked
Block 4 — Overlay and the seam
  • Wallets, processors, BaaS, open banking / data rights
  • Stablecoins as a settlement rail that still has to land at a bank
  • Agent-initiated checkout: who authorized, who is liable
  • Embedded pay-in/pay-out, commercial, cross-border — who already owns the layer
Final project (team) + individual defense
  • Pick one seam. Build the thin product: economics, state machine, failure book, liquidity plot
  • GitHub Pages an operator can use. Name the firm that owns the adjacent layer.
  • Individual defense: fee stack, intra-day hole, exception P&L, your code. No teammate as proxy.

V 2026.09.18 草稿   |   教授 JAKE VESTAL   |   jacob.vestal@duke.edu

01 // 课程说明

一笔支付，是一次状态变更，加上一项法律上的请求权。本课程顺着这项请求权，穿过各条支付轨道——银行卡、ACH、电汇、FedNow/RTP、SWIFT，以及 ISO 20022 迁移——再穿过轨道之上的叠加层：钱包、支付处理商、银行即服务、开放银行与数据权利，以及被当作结算工具、而不是投机资产来用的稳定币。本课程不是一门加密货币选修课，也不同于 FINTECH 520 的产品概览。

这个市场里的优势，并不属于最先做出极速前端的人。优势属于控制身份的人、控制轨道之上那层软件的人，以及控制编排的人——编排把几十年的基础设施藏在一次授权后面。学生要为授权、清算、结算和失败建立模型：退回、拒付、代理行流动性、负载之下的账本行为，以及当发起实时支付的不是人、而是自动代理时，什么会坏掉。

课程作业是定量的，既交出数字，也交出系统：一条轨道的单位经济、一本结算风险账、一套退回与异常引擎，以及一条欺诈评分对误报的曲线。作业放在 GitHub Pages 上，让运营人员能够直接使用那张图。重点放在现有格局尚未占据的接缝——嵌入式收款与付款、商业与跨境资金流、对账与异常、由代理发起的结账，以及最终仍须落进银行的结算。

鼓励用 AI 写代码、抽取文档。交换费的计算、流动性，以及失败情形，仍由学生本人负责。

02 // 可选教材

无指定教材。一手材料：网络费率表、NACHA 操作规则节选、FedNow / RTP 产品说明、一张卡组织拒付原因代码表、一份 ISO 20022 报文样本。

有用的案头读物，不必通读：一本当前的支付行业入门；国际清算银行（BIS）与美联储关于即时支付和批发结算的论文。对本课程而言，卡组织的 PDF 比教材有用。

03 // AI 政策
强烈鼓励使用 AI。你可以用任何模型来写编排代码、解析卡组织的 PDF，或起草备忘录。你对交上来的一切负全部责任：模拟器要能跑，单位经济要算对，读者不必去问那个工具你到底是什么意思，就能跟上状态机。结算风险估错了，或者拒付决策树是错的，那就是你的成绩。

05 // 学习目标
01 画出任意一条主要轨道上的支付状态机：授权、清算、结算时谁是主责任方；法律上的请求权何时转移；一次退回或拒付撤销了什么。
02 计算单位经济：交换费 + 卡组织 + 收单机构 + 处理商 + 欺诈 + 奖励 + 在途资金成本 + 延迟结算的资金成本。给出单笔交易和组合层面的边际贡献。
03 测算结算与代理行流动性：净额与全额、预注资、在途敞口，以及一个被推迟的 ACH 批次对现金意味着什么。画出一天之内的敞口。
04 建立失败系统：退回、拒付、R 代码、异常队列。衡量一条欺诈规则的误报成本，而不是只看 AUC。
05 把一家公司放回技术栈上。说清谁已经拥有身份、轨道和编排。指出相邻的接缝（嵌入式、跨境、对账、代理结账、最终落入银行的稳定币结算），并做出一个薄版本。
06 发布到 GitHub Pages。没有队友代讲，也能把账本和损益答辩清楚。
06 // 暂定课程安排
模块 1 — 状态变更 + 法律上的请求权
  • 授权、清算、结算，是三套时钟
  • 谁是主责任方：发卡行、收单机构、卡组织、代理行、TCH、美联储
  • ISO 20022 是一种报文，不是一种信仰
  • 实验：把一笔银行卡支付和一笔 ACH 贷记画成状态机；列出每一本发生变动的账
项目 1 — 一条轨道的单位经济
  • 交换费 + 卡组织 + 收单机构 + 处理商 + 欺诈 + 奖励 + 在途资金
  • 同一笔 100 美元的销售，银行卡、ACH、FedNow 各算一遍；单笔，以及每天 1 万笔时的边际贡献
  • 敏感性：结构变化、交换费监管、欺诈率上升 40 个基点
  • 交付：工作簿 + 运营人员认得出来的 Pages 瀑布图
模块 2 — 支付轨道
  • 银行卡：双报文与单报文，拒付窗口期
  • ACH：批次、退回（真正要紧的 R01–R29）、当日 ACH
  • 电汇 / SWIFT / 代理行：往账账户（nostro）、封面支付（cover payment）、代理行的流动性
  • FedNow / RTP：即时、大致不可撤销；“收款请求”改变了什么
  • 实验：时延与终局性对照表；画出一个营业日内各轨道的在途敞口
项目 2 — 结算风险账
  • 模拟一家处理商的一天：请款、批次 ACH、即时出款、收到的退回
  • 现金、应付商户款、应收卡组织款、预存的 RTP 余额
  • 把这一天打断：ACH 窗口推迟、卡组织中断、退回率升到 2%
  • 交付：时间序列账本 + 你必须补上的最大日内资金缺口
期中测验 — 闭卷。状态机、费用结构、一个流动性数字。考前一周发放学习指南。
春假
模块 3 — 失败、欺诈、身份
  • 拒付和 R 代码是损益，不是一张客服工单
  • 账户盗用（ATO）和授权推送支付欺诈（APP fraud），对照反洗钱的时钟（毫秒对可疑活动报告）——不要混为一谈
  • 身份：当前端是银行即服务的合作方时，谁拥有 KYC
  • 实验：给一串交易打分；画出精确率–召回率，以及误报的美元成本
项目 3 — 异常引擎
  • 队列：退回、拒付、对不上的账、被退回的代理发起支付
  • 服务时限对资本：一笔异常可以搁多久，才会变成资金缺口
  • 交付：Pages 运营控制台 + 队列放着不处理的预期损失
模块 4 — 叠加层与接缝
  • 钱包、处理商、银行即服务、开放银行 / 数据权利
  • 稳定币是一条结算轨道，最终仍须落进银行
  • 由代理发起的结账：谁授权，谁承担责任
  • 嵌入式收款与付款、商业、跨境——谁已经拥有这一层
期末项目（小组）+ 个人答辩
  • 选一条接缝。做出薄产品：经济、状态机、失败账、流动性图
  • 运营人员能用的 GitHub Pages。点名拥有相邻层的那家公司。
  • 个人答辩：费用结构、日内缺口、异常损益、你的代码。不许队友代讲。
期末 — 小组成果 + 个人答辩

暂定。轨道会变；授权 / 清算 / 结算和损益不会。
